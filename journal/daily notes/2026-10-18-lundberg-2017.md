## Source

PDF: https://papers.nips.cc/paper_files/paper/2017/hash/8a20a8621978632d76c43dfd28b67767-Abstract.html (the proofs are in the Supplementary Material linked from the same page)
Code/demo: https://github.com/slundberg/shap (footnote 1 of the paper)

## TL;DR

This is the paper that introduced **SHAP (SHapley Additive exPlanations)**. The authors show that six existing explanation methods, including **LIME**, share the same form: they explain a prediction as a **sum of per-feature contributions** ("additive feature attribution"). Using results from cooperative game theory, they prove that only one set of values in this class has three desirable properties (**local accuracy, missingness and consistency**): the **Shapley values**. They propose SHAP values as a single measure of feature importance, and new ways to estimate them (e.g. **Kernel SHAP**, a version of LIME with a specific weighting that recovers Shapley values). For us, it's the foundational citation for the SHAP method we use. It also explains in theory **why LIME and SHAP can give different answers** for the same prediction.

## Key takeaways

- **Explanation model (§2):** treat any explanation of a prediction as a simpler model g of the original model f.
  - Most methods work on "simplified inputs" x′ (e.g. whether each word is present or not), which a mapping h_x turns back into the original input.
- **Additive feature attribution (Definition 1, Eq. 1):** g(z′) = φ₀ + Σ φᵢ z′ᵢ, with z′ ∈ {0,1}ᴹ.
  - Each feature gets an effect φᵢ, and adding them up approximates the model's output.
  - **Six existing methods fit this form:** LIME, DeepLIFT, layer-wise relevance propagation, Shapley regression values, Shapley sampling values and Quantitative Input Influence.
- **Three properties (§3):**
  - **Local accuracy (Property 1):** the attributions plus the base value φ₀ add up exactly to the model's output for that input. φ₀ is the output with all simplified inputs "missing".
  - **Missingness (Property 2):** a feature that's missing from the input gets zero attribution.
  - **Consistency (Property 3):** if a model changes so that a feature's contribution increases or stays the same, that feature's attribution shouldn't decrease.
- **Theorem 1 (uniqueness):** only one explanation model in this class satisfies all three properties: the Shapley values (Eq. 8). It builds on Young (1985).
  - The authors conclude that methods **not** based on Shapley values violate local accuracy and/or consistency.
  - This uniqueness holds "for a given simplified input mapping h_x".
- **SHAP values (§4):** the Shapley values of a conditional expectation of the model, E[f(z) | z_S] (Fig. 1).
  - The base value E[f(z)] is what the model would predict if no features were known. Each φᵢ is the change in expected prediction when that feature is added, averaged over all orders of adding features.
  - Computing them exactly is "challenging", so the estimation methods use two optional simplifying assumptions: **feature independence** (Eq. 11) and **model linearity** (Eq. 12).
- **Estimation methods:**
  - **Model-agnostic:** Shapley sampling values (already known) and **Kernel SHAP** (new).
    - LIME's choices of loss, weighting kernel and regularisation are "made heuristically" and **do not recover the Shapley values**. So LIME can violate local accuracy and/or consistency.
    - **Theorem 2 (Shapley kernel)** gives the specific weighting kernel, squared loss and zero regularisation that make LIME's weighted linear regression produce Shapley values. This is Kernel SHAP.
  - **Model-specific:**
    - **Linear SHAP:** φᵢ = wⱼ(xⱼ − E[xⱼ]) for linear models, assuming feature independence.
    - **Low-Order SHAP:** efficient when the number of features is small.
    - **Max SHAP:** O(M²) time instead of O(M·2ᴹ) for a max function.
    - **Deep SHAP:** DeepLIFT adapted to approximate SHAP values. The authors show DeepLIFT already approximates SHAP values if its reference value is read as E[x], assuming feature independence and a linear model.
- **Experiments (§5):**
  - **Efficiency (Fig. 3):** on dense (all 10 features) and sparse (3 of 100 features) decision-tree models, Kernel SHAP gets accurate estimates with fewer model evaluations than Shapley sampling (200 replicate estimates per sample size). LIME's values "can differ significantly" from the SHAP values.
  - **Human intuition (Fig. 4):** Amazon Mechanical Turk participants assigned credit in two simple models:
    - a sickness score depending on fever and cough (30 people);
    - a "max" profit-sharing story between three men (52 people).
    - The authors report "much stronger agreement" between human explanations and SHAP than with LIME or the original DeepLIFT.
  - **MNIST (Fig. 5):** a convolutional digit classifier, masking 20% of pixels to switch the prediction from 8 to 3 according to each method's attributions. Over 20 random images, methods closer to SHAP values produced larger changes in log-odds. SHAP and LIME were both run with 50k samples, and LIME was modified to use single-pixel segmentation.
- **Main argument:** the SHAP framework unifies existing methods, and its desirable properties give "a strong incentive for all additive feature attribution methods to use SHAP values". Stated next steps: faster model-specific methods with fewer assumptions, interaction effects, and new classes of explanation model.

## Why it matters for our project

1. **It's the core Methods citation for SHAP.** Both experiments use SHAP to say how much of Detoxify's score comes from each word, so the report's Methods section should cite this as the origin of SHAP values and their properties.
2. **Local accuracy is the additivity check we already run.** Our EXP2 spec checks that the base value plus the sum of SHAP values reconstructs the model's log-odds output (W4-L01 p3–4). That's Property 1 from this paper. It's also what makes statements like "X% of the decision rests on the identity word" meaningful: the parts add up to the whole.
3. **It explains in theory why SHAP and LIME can disagree.** LIME and SHAP fit the same kind of explanation model. LIME's weighting is heuristic, so it doesn't recover Shapley values, while Kernel SHAP's weighting does. That's a principled reason to expect the SHAP–LIME disagreement we measure (with the Krishna et al. 2022 metrics). *(Our LIME 10-run stability test measures something else: randomness from LIME's sampling, which this paper doesn't study.)*
4. **The guarantees are about the model, not about fairness.** Local accuracy and consistency mean SHAP faithfully decomposes *the filter's* score. Nothing in the paper says whether that score is right. 

## Concerns / why we should be careful with it

- **"Unique" depends on what "missing" means:** Theorem 1 holds "for a given simplified input mapping h_x". In practice, the values depend on how missing features are represented (the base value, the background or the masking). For text, that's how a removed word is masked, which the paper doesn't cover.
- **Estimation relies on simplifying assumptions:** the practical estimators assume feature independence (Eq. 11) and, for some, model linearity (Eq. 12). Words in a sentence are not independent, so the estimates are approximations.
- **No text experiments:** the evaluations are on decision trees, toy models in the user studies, and MNIST images. Nothing in the paper tests SHAP on text classifiers like Detoxify.
- **Small, simple user studies:** 30 and 52 participants on toy models. The main text reports "much stronger agreement" without statistical tests, and assumes "good model explanations should be consistent with explanations from humans who understand that model".
- **Not the explainer we use:** with a text masker, the `shap` library's `shap.Explainer` uses its Partition explainer (as noted in our Krishna et al. review), which isn't one of the estimators in this paper. Cite this paper for SHAP values and their properties, not for our exact algorithm. *(This comes from the `shap` library, not from the paper.)*
- **Later work challenges it:** Slack et al. (2020) show SHAP and LIME can be fooled by adversarial models, and Krishna et al. (2022) show explanation methods often disagree in practice. The theoretical properties don't make SHAP outputs trustworthy in every setting.

## Where this ties back into XAI module content

- **SHAP additivity (week 4, W4-L01 p3–4):** the module's additivity property is this paper's local accuracy (Property 1). It's what our code checks.
- **Global vs local explanations (week 4, W4-L01 p6):** the paper focuses on *local* methods that explain a single prediction. Our averages of SHAP values per identity word stack local explanations into a global one.
- **Signed vs absolute SHAP (week 4, W4-L01 p9–10):** Fig. 1 shows features pushing the prediction both up and down (φ₄ is negative). That's why we plot signed SHAP values and not just mean |SHAP|.
- **LIME (week 5, W5-L02 p2):** the paper describes LIME as weighted, penalised linear regression on sampled inputs, with a heuristic kernel. This is the same method whose sampling variability we measure.
- **shap-exercises notebook (explain log-odds, not probability):** we explain Detoxify's log-odds so the attributions are additive. The paper's own MNIST evaluation also reports changes in log-odds.
- **Don't infer causality from attributions (Textbook p53):** SHAP values describe how the model's output changes when features are present or missing. They don't establish causes in the world.
